# v3.10 — Career stats panel + PFR similarity audit

**Date:** 2026-06-02

Two changes from Phil's 2026-06-02 ask:

1. **Career stats on the player profile.** Every ranked player's static
   profile page (`dynasty_site/players/<slug>.html`) now renders a
   *Career Stats* section immediately above the Fantasy-Point Arc
   Comparables table. The data is scraped from Pro Football Reference
   via the existing v2.4 PFR plumbing
   (`dynasty.sources.pro_football_reference_seasonal`); a thin parser +
   per-player JSON cache lives in
   `dynasty.sources.pfr_career_stats`. The same page serves both the
   Similarity Scores landing page and the Dynasty Rankings page —
   they already link into a single per-player profile.

   - **Columns by position:**
     - QB: Year · Team · GP · Cmp · Att · Cmp% · Pass Yds · Pass TD · INT · Rush Att · Rush Yds · Rush TD · FP
     - RB: Year · Team · GP · Rush Att · Rush Yds · Rush TD · Tgt · Rec · Rec Yds · Rec TD · FP
     - WR / TE: Year · Team · GP · Tgt · Rec · Rec Yds · Rec TD · Rush Att · Rush Yds · FP
   - **Fantasy points** are computed in Superflex PPR (1 PPR · 4 pt
     pass TD · 6 pt rush/rec TD · −2 INT · −2 fumble). Bottom row is
     career totals.
   - **Caching.** Two layers: the raw PFR HTML cache from v2.4
     (`data/pfr_cache/players/*.html`) and a new JSON cache
     (`data/cache/pfr_career_stats/*.json`) so re-runs don't re-parse.
     Both are gitignored.
   - **No-network fallback.** If a player's PFR id can't be resolved
     (or the Wayback fetch fails), the Career Stats section is silently
     omitted — the rest of the profile renders unchanged.
   - **Skip switch.** Set `DFM_SKIP_CAREER_STATS=1` to bypass the panel
     entirely during a fast local rebuild.

2. **PFR similarity sanity-check audit.** New runnable script
   `scripts/audit/pfr_similarity_audit.py` compares our top-10
   Fantasy-Point Arc Comparables against PFR's `#all_sim_scores`
   **Career** row for the top-50 Dynasty Rankings players. Output:
   `docs/audits/pfr_comparison_audit.md` (per-player tables + themes)
   and `docs/audits/pfr_audit_summary.csv` (overlap@10, overlap@20,
   Jaccard, miss/extra counts per player).

   **First-run signal (7 of 50 auditable — PFR only renders sim_scores
   for veterans with enough seasons in the cached snapshots):**
   - Average overlap@10 with PFR Career row: **0.43 / 10**
   - Average Jaccard: 0.023
   - Themes (in order of strength):
     1. **Active-modern cohort under-represented** — PFR's Career row
        for veteran QBs surfaces currently-playing peers (Mahomes,
        Burrow, Herbert, Goff, Prescott); ours skews to retired
        all-time greats.
     2. **Mid-tier-veteran blind spot** — PFR repeatedly cites
        competent journeymen (Aaron Brooks, Trent Green, Danny White,
        Bert Jones, Matt Schaub); we filter them out via wash-out-rate
        + long-career bias, so Mayfield / Darnold / Goff profiles
        match only to Brady / Brees / Manning, inflating projections.
     3. **Pre-1999 corpus pulling hard** — The v3.9 corpus expansion
        is *driving* the projection on most veteran QB profiles, not
        just sanity-checking it. Currently 20 pre-1999 names appear as
        "extras" across 7 audited players.
     4. **Durable-legend over-pull on mid-tier query players** — When
        the query player isn't elite, our top-10 still cites Brady /
        Brees / Manning / Favre because their post-age-N fp/g curve
        aligns; PFR's Bill-James method weights career
        shape-and-magnitude together and stays away.

   See `docs/audits/pfr_comparison_audit.md` for per-player detail and
   the full set of fixes proposed in the Themes section.

## Plumbing changes

- `src/dynasty/sources/pfr_career_stats.py` — new module: builder
  (`build_career_stats`), HTML renderer (`career_stats_html`),
  per-player JSON cache.
- `src/dynasty/report.py` — `_build_player_page` accepts an optional
  `career_stats_html` argument and splices it immediately above the
  Comparables section. `generate_site` resolves each row's PFR id via
  the new `_load_gsis_to_pfr` helper and stamps the panel in, with a
  per-row exception handler so a single bad scrape never breaks the
  build.
- `scripts/audit/pfr_similarity_audit.py` — the audit runner; uses the
  rendered player pages as the source of truth for our top-10 comps
  (so it audits exactly what the user sees) and re-uses
  `pro_football_reference_seasonal.fetch_player_bio_html` for PFR
  bios.
- `tests/test_pfr_career_stats.py` — unit tests for QB/RB/WR career
  shape against checked-in PFR fixtures (Manning / Smith / Rice) plus
  set-overlap math + name-normalisation tests against the audit
  module.

## Known caveats

- PFR's `#all_sim_scores` block doesn't render in many Wayback
  snapshots for early-career players (Trevor Lawrence, Justin Herbert,
  Jahmyr Gibbs, etc.). The audit reports these as `skipped: no
  sim_scores table` and the themes section reports the audit denominator
  alongside the rate metrics. Re-running once Wayback re-captures
  these pages will expand the audit corpus without code changes.
- The v3.10 panel is cosmetic — it doesn't feed back into the model
  scoring. Themes from the audit are the actionable artefact for the
  next model PR.
